# Matrixly i18n

Client-side translations for the static marketing site and agent product pages.

## Supported languages

| Code | Native name   | Notes                          |
|------|---------------|--------------------------------|
| `en` | English       | **US English** (default)       |
| `es` | Español       | Neutral LatAm/Spain            |
| `fr` | Français      | French                         |
| `ar` | العربية       | Modern Standard Arabic + RTL   |
| `bn` | বাংলা         | Bengali                        |
| `de` | Deutsch       | German                         |
| `ms` | Bahasa Melayu | Malay                          |

Preference is stored in `localStorage` under **`matrixly-lang`**.

## Files

| Path | Role |
|------|------|
| `i18n/en.json` | Source of truth (US English) |
| `i18n/{es,fr,ar,bn,de,ms}.json` | Locales (same key tree as `en`) |
| `js/i18n.js` | Loader, `dir`/`lang`, `data-i18n*`, **catalog cache** |
| `js/lang-selector.js` | Globe language control (no country flags/codes) |

### Caching

`js/i18n.js` caches each locale catalog in:

1. **Memory** (same tab session)
2. **`sessionStorage`** key `matrixly-i18n-catalog:v2:{lang}`
3. Browser HTTP cache (`fetch` with `force-cache`)

After the first language loads, other locales are **prefetched** on idle so switches feel instant.

To bust caches after a deploy that changes JSON content, bump `CACHE_VERSION` in `js/i18n.js`.

### Markup attributes

```html
<span data-i18n="nav.agents">Agents</span>
<p data-i18n-html="hero.sub2">…</p>
<input data-i18n-attr="placeholder:liveDemo.placeholder" />
```

Leave English text inside elements as fallback when JS is disabled.

**Do not translate** product/agent brand names: Matrixly, SocialForge, BookWise, SupportForge, InvoiceForge, etc.

## Language selector

- Globe icon trigger (no flag emoji / no `GB` / `EN` country codes — Windows often renders flags as two-letter codes).
- Menu lists native names only: English, Español, Français, العربية, বাংলা, Deutsch, Bahasa Melayu.
- Injected left of the theme toggle when present; otherwise placed in the page header.
- Accessible: `role="listbox"`, keyboard arrows, Escape, outside click.

## Adding or updating strings

1. Add keys to **`i18n/en.json`** only (keep structure nested under sections: `nav`, `hero`, `common`, …).
2. Mark the UI with `data-i18n="section.key"` (English fallback text stays in HTML).
3. Fill other locales:

```bash
# Prefer API keys when available
export DEEPL_API_KEY=...          # es, fr, de
export ANTHROPIC_API_KEY=...      # ar, bn, ms (or OPENAI_API_KEY)

node scripts/i18n-translate.mjs
node scripts/i18n-translate.mjs --dry-run
node scripts/i18n-translate.mjs --force es,fr
```

Without API keys the script **never empties** existing locale files; it only fills missing keys (English fallback if needed).

4. Wire many pages at once:

```bash
python scripts/wire-site-i18n.py
```

5. Validate:

```bash
python scripts/validate-i18n.py   # if present
node scripts/i18n-translate.mjs --dry-run
```

## CI

`.github/workflows/i18n-check.yml` runs on PRs/pushes that touch `i18n/` or i18n scripts:

- Fails if any locale is empty or missing keys vs `en.json`
- Comments on the PR with missing paths
- Dry-runs the translate script (non-blocking)

## Manual QA checklist

- [ ] Selector shows globe + “English” (not `GB EN`)
- [ ] Switching language updates marked strings site-wide
- [ ] Choice survives reload (`matrixly-lang`)
- [ ] Arabic sets `dir="rtl"` and does not break nav
- [ ] Theme toggle still works
- [ ] Agent names (SocialForge, BookWise, …) stay English
- [ ] No console errors; fallback to English if a locale fails to load
